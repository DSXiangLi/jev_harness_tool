对比总结

场景gate noulno_skill_needed 选项关键差异
1. 明确命中 ✓ 正确 ✓ 正确 两者都能正确推荐
2. 纯文字够用 ✓ gate 拒绝 ✓ no_skill_needed 胜出 两者都能正确拒绝
3. roster 覆盖盲区 ✗ gate 误放行 ✓ none 正确拒绝 核心差异：gate 只看 query 不知道 roster 内容；none 同时看 query + roster
4. 关键词陷阱 ✓ gate 拒绝 ✓ no_skill_needed 胜出 gate 靠"不需要操作"拒绝；none 靠"scope 不匹配"拒绝（更精确）
5. 双技能模糊 ○ low_margin ○ low_margin 两者都无法区分，都靠 margin 降级

结论

• 场景 3 是核心差异：gate noul 只看 query 不知道 roster 内容，无法识别"请求需要技能但 roster 里没有"。no_skill_needed 选项放进 choice criteria，同时看到 query + 全部技能描述，能正确识别 roster 覆盖盲区。

• 场景 2/4 中两者表现相当：gate 靠请求意图拒绝，none 靠 scope 不匹配拒绝。none 的拒绝理由更精确（"看了 roster 发现不匹配"），gate 的拒绝理由是间接的（"请求不需要操作"）。

• no_skill_needed 选项额外优势：少 1 个 question 的 token；不需要单独的 gate_criteria 写进 state；语义更直接（"roster 是否覆盖"比"请求是否需要技能"更贴近实际判断）。

• no_skill_needed 选项的代价：none 的概率是归一化分布的一部分，语义随 N 变化（3 个技能时 none 占 1/4，60 个技能时占 1/61）。但实际上 jev 模型按 criteria 语义分配概率，不按均匀先验，所以这个影响有限。

• 建议：用 no_skill_needed 选项替代 gate noul。在单步路径中，choice criteria 加入 no_skill_needed 选项；在两步路径中，step 1 用 per-skill noul 的 max(p_i) < threshold 做存在性检查，step 2 的 choice 加入 no_skill_needed 选项。
