JEV HARNESS TOOL · 决策层原理解析

jev：harness 决策层的
专职裁判

主 LLM 负责生成，jev 只负责判断。它像一个闪电般快速的裁判：你给它一段上下文（state）和一组问题（questions），它一次性返回校准过的概率。本页以 skill_search 工具为例，完整走一遍「该不该加载某个技能」是如何被裁决的。

query: 「帮我审查一下这个设计文档」

01jev 的三种问题类型

调用方发送 {state, questions}，jev 一次 /decide 回答全部问题。问题类型定义在 core/questions.py。点「提问」看看它们各自返回什么。

choice
单选题。给 instructions + criteria（1–255 个「选项名 → 精确定义」的 map），返回各选项的归一化概率分布，胜者必须是 argmax。
criteria = { s7: "设计文档审核: 系统化审核设计文档的完整性…", s19: "提交后文档回扫: 提交前强制同步四类文档…", __no_skill_needed__: "roster 中不需要任何技能：(a) 纯文字可答; (b) 需要流程但 roster 没有对应技能…" }

02完整数据流：一次 skill_search 调用

输入：query + skills[{name, description}] + 一组阈值参数（全部有默认值、响应原样回显）。下面以 51 个技能为例走信息最丰富的两步路径。

分流点 = switch_threshold（默认 50）。auto 是唯一模式。

① 参数校验 + 位置 key

校验阈值 ∈ [0,1]、正整数等；给每个技能分配 wire 位置 key，调用方的 name 原样透传，避免对象 key 冲突。
s0 · s1 · s2 · … · s50

② description 截断

超过 description_max_chars（默认 500）头部截断并标记 truncated:true。
⚠ 被截断的技能永不自动 select，最多降级 review。

③ 构造共享 state（只发一次，随每批重发）

{ task: "判断 roster 中哪个技能最适合查询，或是否不需要任何技能", context: "技能是完成某类任务的指导说明/流程规范， 不是仅仅共享关键词的工具…", query: <用户查询> }

03裁决：三重门

step 2 返回后：winner = argmax，p1 = 其概率，margin = 冠亚军概率差。三重门全部通过才自动 select（且该技能未被截断）。点下面的场景试试：

门 1 · 冠军概率
—
p1 ≥ threshold (0.30)
门 2 · 冠亚军差距
—
margin ≥ margin_threshold (0.15)
门 3 · fits 复核
—
fits[winner] ≥ fits_threshold (0.30)

margin 是第二判据（原则 5）：避免「51% vs 49%」式的勉强裁决被当成确定答案。另：best_fits < 0.30 时无论 choice 多自信都判 none_fit；winner 被截断 → review(reason=truncated)。

所有终态一览

select
p1 ≥ 0.30 且 margin ≥ 0.15 且 fits ≥ 0.30，且未截断 → 自动选中（绿色）
review · low_margin
p1 达标但 margin < 0.15 → 冠军和亚军都进 review，交人/主 LLM 定夺
review · below_threshold
p1 < 0.30 → 冠军进 review
review · truncated
winner 的 description 被截断 → 永不自动 select
none_relevant
逃生舱 __no_skill_needed__ 胜出，或存在性门拦截 → 其余全部 skip
none_fit
best_fits < 0.30 → 入围者全部 skip（choice 自信但复核不通过）
invalid_response
jev 答案缺失/畸形 → 该技能标红，只影响该项，不炸掉整个 batch

05Fail-closed 与重试纪律

jev 调用是付费的，且没有幂等键——一次歧义网络错误的「重发」可能变成双倍计费。所以重试纪律是硬规则。

❌ 歧义网络错误：绝不重发

连接重置、TLS 失败——请求可能已被服务端处理，重发 = 双倍计费

双层校验（原则 13）。transport 层校验响应 envelope：结构完整、概率 ∈ [0,1]、choice 胜者必须是 argmax；工具层再做语义校验（类型对不对、key 集对不对）。
局部失败不扩散（原则 12）。某个技能的答案缺失/畸形 → 该技能标 invalid_response，其余技能照常裁决；只有整批失败（如 401/403/余额不足）才让整个调用失败。
绝不伪装（原则 12）。confidence 未知时视为不满足任何阈值；被截断的输入永不返回自动通过的结论。
阈值即参数（原则 11）。所有阈值都是可选工具参数、带默认值；响应回显实际使用的阈值与完整 usage，各接入方按自己的数据调校。

07一句话总结

skill_search 把「该不该加载技能」这个判断，从主 LLM 的直觉，变成 jev 的校准概率 + 多重闸门的可审计决策：快、便宜、可复现，并且永远知道什么时候该说「我不确定」。
