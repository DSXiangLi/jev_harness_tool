结论：问题在 instructions 措辞，不在机制

改进效果：2/6 → 6/6（+4 场景翻转）

仅修改 instructions 措辞，不改机制（choice + no_skill_needed 选项），准确率从 2/6 提升到 6/6。4 个失败场景全部翻转。

旧版的问题

旧版说 "best matches the query" 和 "Judge by scope match, not keyword overlap"。问题在于"scope match"对 jev 来说太模糊——mcp-builder 的 scope 是"MCP 服务"，查询"检查 MCP 服务"也在 MCP scope 内，所以 jev 认为是 scope match。旧版没有告诉 jev 技能的本质是什么。

新版的改进

1. 定义技能本质："A skill is a set of instructions, guidelines, or best practices for accomplishing a specific type of task — not merely a tool or API that shares keywords with the query."
2. 强调"需要遵循"："the assistant would actually need to load and follow to answer, solve, or complete the user's request"
3. 明确排除条件："Do NOT pick a skill merely because it shares topic keywords, operates in the same domain, or is tangentially related"
4. no_skill_needed 描述更具体：用 "checking MCP quality" vs "building MCP servers" 和 "design doc review" vs "post-commit doc sync check" 等真实对比示例说明何时选择

启示

在设计 jev 决策工具时，instructions 措辞是影响决策质量的最大杠杆。机制（choice/noul/gate/fits）提供框架，但 jev 模型的判断质量取决于 instructions 如何定义"匹配"的语义。好的 instructions 应该：
• 定义评估对象的本质（技能是指导说明，不是语义相关的工具）
• 用真实对比示例说明边界（构建 vs 检查、创建技能 vs 创建 MCP 服务）
• 明确排除条件（不要因为关键词重叠或领域相同就选）
