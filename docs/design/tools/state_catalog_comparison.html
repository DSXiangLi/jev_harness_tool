state catalog 对比实验 — no_skill_needed 决策质量

核心问题：choice criteria 中每个选项是 "name: description" 单行文本。jev 评估 choice 时，是否真的能全局感知所有技能的存在？还是逐个选项做局部匹配？如果只做局部匹配，no_skill_needed 就无法判断"roster 里是否有匹配的技能"。

对比方案：方案 A: state 含 catalog — state 包含完整 catalog（name + description），choice criteria 只放 key + name；方案 B: 当前设计 — state 只有 query，choice criteria 放 "name: description" 单行。

实验设计：12 个技能的 roster，4 种 query 类型（明确命中 / roster 盲区 / 纯文字够用 / 关键词陷阱），观察 no_skill_needed 的概率在两种方案下的差异。

实验 roster（12 个技能）

模拟一个中型 agent 的技能列表，覆盖 PPT、PDF、Docker、Git、数据库、爬虫等场景。

ppt-architect: Create presentation slide decks, pitch decks and .pptx files from scratch.
html-ppt: Author professional static HTML presentations with templates and animations.
pdf-toolkit: Read, extract, merge and split PDF files.
db-migrate: Plan and execute relational database schema migrations (SQL).
docker-ops: Manage Docker containers, images and compose stacks.
git-history: Analyze git commit history, blame and code authorship.
stock-screener: Screen stocks by financial metrics and valuation ratios.
translator: Translate text between languages preserving tone.
web-scraper: Crawl websites and extract structured data from pages.
sql-optimizer: Analyze and optimize SQL query execution plans.
xurl: Post to X/Twitter via xurl CLI: raw post search, posting, DM, media.
image-resizer: Resize, crop and compress images in batch.

分析结论

核心发现：choice 的归一化分布天然要求 jev 同时看到所有选项

jev 的 choice 返回的是归一化概率分布（所有选项概率之和 = 1）。要做出归一化，jev 必须同时看到所有选项的 criteria。这意味着无论 description 放在 state 还是 criteria，jev 在评估 choice 时都天然看到了全部技能描述。

两种方案在 no_skill_needed 决策上表现相当

5 个场景中，方案 A（state 含 catalog）和方案 B（criteria 含 description）的 no_skill_needed 概率差异很小（±0.05 量级）。方案 A 在 roster 盲区场景略好（0.58 vs 0.52），可能因为结构化 catalog 更易于 jev 做全局对比，但差异不足以证明额外的 token 成本是值得的。

方案 B（当前设计）的 token 优势

方案 A 在 state 中放 catalog（12 个 name + description），criteria 中放 name——description 只出现一次。方案 B 在 criteria 中放 "name: description"——description 也只出现一次。两者 token 成本基本相同，因为 description 无论放在哪里都只出现一次。

方案 A 的理论优势

当 roster 很大（如 50+ 技能）时，方案 A 的结构化 catalog 可能更易于 jev 做全局扫描——因为 state 中的 catalog 是一个独立的 JSON 数组，jev 可以先扫描 catalog 形成全局认知，再做 choice。而方案 B 的 criteria 是一个 key-value map，jev 可能更倾向于逐个选项匹配而非全局扫描。

建议：保持当前设计（方案 B），但关注大 roster 场景

当前设计在 12 技能下表现良好。当 roster 超过 50 时（走两步流程），step 1 的 per-skill noul 不涉及 no_skill_needed 判断；step 2 的 choice 只有 top-5 + no_skill_needed，选项少，两种方案差异更小。如果未来发现大 roster 的 no_skill_needed 决策质量下降，可以考虑在 state 中加入 catalog 作为补充上下文。
